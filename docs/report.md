# 카페 샘플 DB 미니 리포트

분석 대상은 2026-09-01~2026-10-04에 생성한 가상 주문 16건이다.
금액은 원이며, 주문 상태가 `completed`인 13건만 판매로 계산한다.
접수 1건과 취소 2건은 매출·판매량·반복 구매 지표에서 제외한다.
이 결과는 학습용 데이터의 집계이며 실제 점포 성과를 나타내지 않는다.

최종 SQL: [bonus/03_report.sql](../bonus/03_report.sql).

## 1. 월별 완료 주문과 매출

정의: 주문시각의 월별로 완료 주문 건수와 `수량 × 주문 당시 단가`의 합계를 구한다.
상세 조인에 따른 주문 중복은 `COUNT(DISTINCT order_id)`로 제거한다.

| 주문 월 | 완료 주문 | 매출 |
|---|---:|---:|
| 2026-09 | 9건 | 104,800원 |
| 2026-10 | 4건 | 51,500원 |
| 전체 | 13건 | 156,300원 |

실행 증거: [M01](../results/m01.txt).
10월 데이터는 4일까지이므로 두 월의 금액만으로 월간 성장률을 해석하지 않는다.

## 2. 메뉴별 판매량 TOP 5

정의: 완료 주문에 포함된 메뉴별 수량 합계. 수량이 같으면 메뉴 ID가 작은 순서다.
동률 전체를 포함하는 공동 순위 방식 대신 정확히 5개 메뉴를 반환한다.

| 메뉴 | 판매 수량 | 매출 |
|---|---:|---:|
| 버터크루아상 | 8개 | 28,000원 |
| 아메리카노 | 5개 | 15,000원 |
| 초코머핀 | 4개 | 16,000원 |
| 치즈케이크 | 4개 | 24,000원 |
| 카페라테 | 3개 | 13,500원 |

실행 증거: [M02](../results/m02.txt).
판매 수량 순위와 매출 순위는 다르다. 매출에는 변경된 현재 메뉴 가격을 적용하지 않는다.

## 3. 기간 내 반복 구매 고객 비율

정의: `(완료 주문 2건 이상 고객 수 / 완료 주문 1건 이상 고객 수) × 100`.
분모는 전체 가입자가 아닌, 샘플 기간 중 구매한 고객이다.

- 구매 고객: 9명.
- 반복 구매 고객: 3명(고객01·고객02·고객03).
- 비율: `3 / 9 × 100 = 33.33%`.

실행 증거: [M03](../results/m03.txt).
구매 고객이 0명이면 비율은 NULL로 반환한다. 이는 비율을 정의할 수 없다는 의미다.
기간 내 주문 횟수로 정의한 지표이며 코호트 유지율이나 장기 재방문율을 측정하지 않는다.
